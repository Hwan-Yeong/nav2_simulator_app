# Nav Studio 설계 메모

브라우저 UI 에서 맵·로봇·센서·파라미터를 고르고, 실제 Nav2 스택이 로봇을 실시간으로 움직이는 2.5D 시뮬레이션·벤치마크·튜닝 도구.

## 결정 사항

| 항목 | 결정 | 이유 |
|---|---|---|
| UI | 로컬 웹앱 (브라우저), 빌드 도구 없는 vanilla JS + Canvas | 설치 부담 없음, WSL/원격에서도 브라우저로 접속 |
| 백엔드 | Python FastAPI + rclpy 브리지 (WebSocket 스트리밍) | Nav2·시뮬레이터와 같은 ROS 2 환경 |
| 시뮬레이션 | 2D, 실시간 1배속 | Nav2 Humble 제어 루프가 wall-clock 주기라 배속 불가 |
| 로봇 설정 | 2D 상면도 CAD 편집기 + three.js 3D 미리보기 | 2D 내비게이션에 필요한 정보는 상면도로 충분, 3D 는 확인용 |
| 구동 방식 | 차동(diff), 전방향(omni/mecanum), 차량형(ackermann) | |
| 배포 | pip 패키지 + CLI (`navstudio`), Docker 이미지 | ROS 2 가 있는 PC 는 pip, 없는 PC 는 Docker |
| 기본 데이터 | 합성 맵 4종과 시나리오, Everybot 운영 Nav2 params·BT, Everybot 플래너·BT 플러그인 소스 | 현장 맵은 공개 저장소에 넣지 않고, 맵 올리기로 추가 |
| 언어 | UI 한국어, 파라미터 이름은 원문 | |
| 동시 실행 | 슬롯 4개, 슬롯마다 ROS 도메인(기본 91~94)·`ros2 launch` 프로세스 그룹·rclpy Context | 한 서버 프로세스가 여러 Nav2 를 섞이지 않게 다룸. 기동은 2초 간격, lifecycle 활성 확인 |
| 공정한 비교 | ‘동시 출발’ 은 모든 슬롯을 출발점·보행자 초기 위치로 되돌린 뒤 같은 순간에 목표 전송 | 슬롯마다 시작 시각이 달라도 같은 조건에서 비교 |
| 설정 세트 | 스택 + 파라미터 변경을 이름 붙여 YAML 로 저장 (`presets/`) | 슬롯·벤치마크·튜닝이 같은 단위를 주고받음 |
| 맵 배포 | 공개 저장소에는 합성 맵만, 현장 맵은 zip(맵 폴더 + info + 시나리오)으로 가져오기 | 현장 평면도를 공개 저장소에 넣지 않음 |
| 월드 | 2.5D: 점유 격자 벽 + 높이 구간(z0~z1)이 있는 장애물 + 단차 사각형 | 낮은 장애물·공중 장애물·단차를 다루면서 맵 형식(2D)과 실시간성을 유지 |
| 3D 센서 | numpy 광선 계산 (바닥·단차는 해석식, 박스는 OBB slab, 원기둥, 벽은 격자 따라가기) | GPU·물리 엔진 없이 센서 하나 수 ms. ToF·초음파·Depth(거리만)에 충분 |
| 센서 확장 | 센서 종류 = 파이썬 파일 하나 (`SensorType`: 파라미터 스키마, 광선, 측정, 발행, 인식 규칙). UI 폼은 스키마에서 생성 | 새 센서를 앱 코드 수정 없이 추가. 잘못된 파일은 그 종류만 빠짐 |
| 인식 | 로봇 탑재 인식 규칙을 별도 노드로 다시 구현 → `/perception/*` 점구름 → ObstacleLayer | 실제와 같은 판단·확정 지연으로 센서 배치·임계값을 비교. 원시 점 모드와 끄기도 제공 |
| 감지 범위 | 물체 하나를 로봇 주변 칸마다 놓고 센서 종류의 광선·측정·인식 규칙을 그대로 돌림 (닿는 광선이 있는 칸만, 칸 묶음 단위로 교차 계산) | 설계 단계에서 사각지대와 정지 거리 안 감지 여부를 숫자로 확인. 별도 근사 모델을 두지 않아 플러그인 센서와 인식 규칙 변경이 그대로 반영 |
| 라이다 병합 | 각도 구간별 최소 거리로 `/scan` (base_scan) 생성, 개별 `/scan_<이름>` 유지 | 앞뒤 라이다를 합쳐 쓰는 실제 구성 재현 |
| 버전 관리 | `__version__` 단일 출처, CHANGELOG, `scripts/check.py`(pre-commit·CI), `scripts/release.py` | 문서·가이드·이미지 태그가 코드와 어긋나지 않게 |

## 단계 (완료)

1. 핵심: 시뮬레이터 + 파라미터 생성 + 세션 관리 + ROS 브리지 + 서버 + 뷰어
2. UI: 맵 선택, 시나리오 도구, 파라미터 패널, 텔레메트리·로그, 레이어
3. 로봇 설계: 상면도 편집 + 3D 미리보기 + 프리셋 로봇
4. 벤치마크·튜닝: 실행·진행률·결과표·에피소드 재생, Optuna 튜닝·순위표·적용/검증
5. 배포: pip 패키지, CLI, doctor, 플러그인 빌드, Docker, README, 사용 가이드
6. 0.2: 동시 실행 비교, 설정 세트, 맵 관리, 버전·릴리스 체계 (CHANGELOG 참고)
7. 0.3: 센서 라이브러리·플러그인, 2.5D 월드(높이·단차), ToF·초음파·Depth, 인식 노드, 라이다 병합, 슬롯별 로봇
8. 0.4: 로봇 설계의 감지 범위(사각지대) 지도
